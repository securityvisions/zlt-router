# Spec: Replace x-ui with s-ui on the VPS proxy server

Status: ready-for-agent

## What was implemented

The VPS at `85.121.124.158` was migrated from the x-ui/xray panel to **s-ui** (alireza0/s-ui) running a **sing-box core**:

- **x-ui removed** — stopped/disabled, files moved to the backup, service unit removed.
- **s-ui installed** (v1.5.5, non-interactively) — panel `http://85.121.124.158:2095/app/`, subscription `http://85.121.124.158:2096/sub/<client-name>`, fresh admin credentials (set via `sui admin` CLI; stored on the server only).
- **VLESS+REALITY inbound** on 443 — `www.bing.com` dest/SNI, preserved REALITY private key and short ID, clients `parsa`, `test-client`, `tape` (with traffic caps) → the router's existing PassWall node reconnected with **no reconfiguration**.
- **Hysteria2 inbound** on 31800/UDP — clients `jafar`, `parsa-h2`, `tape-h2` (existing auth strings as passwords), salamander obfuscation, self-signed TLS.
- **Routing** restored: `geoip-ir` rule-set → direct, `ip_is_private` → reject, `bittorrent` → reject.
- **Subscriptions** — valid per-client links generated with the public server IP.
- **Firewall (ufw)** — 22, 443, 2095 (panel), 2096 (sub), 31800 udp+tcp; old x-ui panel port (53253) closed.

The router side is unchanged in credentials; on the VPS's failure the router's fail-open watchdog falls back to direct internet and auto-recovers.

## Deviations from the original plan

1. **Failover mechanism** — the plan called for a URLTest auto-failover pair (VLESS primary tolerated via a large tolerance). In practice the URLTest selects the *lowest-latency* node and cannot enforce VLESS-primary, so it repeatedly selected hysteria when hysteria measured faster. A PassWall SOCKS autoswitch (primary VLESS / backup hysteria) was attempted for strict priority, but it is incompatible with the router's fail-open auto-recovery watchdog (its node test cannot test `Socks_*` tcp nodes) and did not demonstrate a reliable switch. **Final decision:** the global `tcp_node` is the VLESS node directly (no automatic node failover), hysteria2 stays manually selectable, and the fail-open watchdog + autorecover provide outage handling.
2. **Hysteria clients** — s-ui uses a global client table (not per-inbound like x-ui), and adding a client to a second inbound via the edit API triggers a sing-box user-rebuild bug (malformed JSON). The hysteria2 accounts were therefore created as separate clients (`parsa-h2`, `tape-h2`, `jafar`) rather than merging into the VLESS clients.
3. **s-ui API automation** — inbounds/clients/routing were created through the panel's frontend API (`/app/api/save`), with the exact data model derived from the s-ui source (tls objects, inbound options, client configs). The GET `inbounds`/`clients` endpoints return a limited view (omitting `config`, `links`, and protocol options), so API-driven *edits* must resend the full DB-derived objects; the sub links are regenerated by editing each client with its DB config.
