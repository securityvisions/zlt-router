# Feature Request Analysis — Device Card Dashboard

**Product:** X28 web dashboard — device management card
**User:** Single technical owner managing 3–5 household devices across 2–3 people
**Goal:** Assign devices to people, see per-device data usage, manage everything visually without SSH

---

## Current State

The devices card shows a flat table: hostname, IP, MAC, and an owner dropdown per row. Assignment works via chip-based UI (tap owner chip → tap person pill). Owner data comes from `devices.json` snapshot generated by `x28-dash-data.sh`.

**What's missing:** the card is a static list. It doesn't tell you anything *about* each device beyond its network identity. No traffic data, no online/offline status, no usage history, no device type.

**Known bug:** Samsung shows `__new__` as owner — the `__new__` placeholder from the assignment flow leaked into owners.conf instead of being replaced by the actual person name.

## Top 3 Prioritized

### #1: Fix `__new__` owner bug (CRITICAL BUG)

**Problem:** When a user taps "➕ new" in the assignment flow, the placeholder `__new__` gets written to owners.conf as the person name instead of being replaced by the typed name. Samsung currently has `__new__` as its owner.

**Root cause:** The `doAssign` function in the dashboard JS checks for `__new__` and prompts for a name, but if the prompt is dismissed or the Enter key fires before the prompt resolves, the raw `__new__` string is sent to the CGI endpoint.

**Fix:** In `x28-dash-actions.sh`, reject `__new__` as a person name. In the JS, ensure the new-person flow is atomic (collect name → then assign).

**Effort:** Trivial · **Risk:** Zero · **Priority:** Immediate

---

### #2: Per-Device Traffic on Device Card

**Problem:** The device card shows hostname/IP/MAC/owner but no traffic data. The user wants to see how much data each device used without going to the Ledger section.

**Solution:** Add a GB column to the devices table showing today's (or this month's) usage per device. Data comes from the current day's owners-d file (or the ledger-range CGI for historical). Each row gets a mini bar showing relative usage.

**Impact:** High — transforms the device card from a static list into a live monitoring view
**Effort:** Medium — needs a CGI endpoint that cross-references devices.json with owners-d data
**Risk:** Low — read-only aggregation

**Test:** Fixture owners-d + devices.json → assert GB values match expected per-device totals

---

### #3: Online/Offline Indicator + Last Seen

**Problem:** The device card doesn't show whether a device is currently connected. The user can't tell if Samsung is online or if it left the network an hour ago.

**Solution:** Add an online/offline dot per device (based on ARP table or lease expiry) and a "last seen" timestamp (from lease renewal time).

**Impact:** Medium — useful for household awareness ("is mom's phone connected?")
**Effort:** Low — ARP table + lease expiry are already available
**Risk:** Zero — read-only

**Test:** Fixture ARP table + leases → assert online devices show green dot, expired leases show gray

---

## Implementation Order

1. **Fix `__new__` bug** (5 min) — critical data corruption, trivial fix
2. **Add per-device traffic column** (1 hour) — highest visual impact
3. **Add online/offline + last seen** (30 min) — easy win, uses existing data

All three are frontend + CGI changes only. Zero router risk.
